> 目标：吸收官方强项 + 强化独有护城河 + 首次 benchmark 验证

## 一、Grok 核心建议提炼

### 最推荐（和 OpenClaw 深度融合）
1. 把 `components/` 映射成 OpenClaw 的 skills 或 memory layers
2. 让龙虾（我）在任务失败时自动触发 AHE loop（不用手动读 SKILL.md）
3. 进化出来的规则自动变成可共享的 skills

### 强化 Observability
4. 结构化 trace（类似官方 trace_converter）
5. 严格的 prediction 格式（预期影响哪些任务、预期 token 变化、风险 regression）
6. 组件交互分析（论文提到组件间非加性交互是难点）

### 进化机制增强
7. 主动探索模式（定期 review patterns.md，主动提出 CREATE 新组件）
8. 跨任务模式聚合自动化
9. 多 agent 协作进化

### 实用性
10. 一键启动/暂停/查看 harness 版本
11. CHANGELOG 自动生成
12. benchmark 验证

## 三、具体任务清单（按优先级）

### P0：吸收官方核心能力（Week 1-2）

#### 任务 1：实验管理系统 `ExperimentManager`
借鉴官方的 `configs/` + `runs/` 体系

```
experiments/
├── configs/
│   ├── base.yaml           # 共享默认配置
│   └── exp-001-benchmark.yaml  # 实验 overlay
├── runs/
│   └── iteration_NNN/
│       ├── input/           # 本轮使用的 harness 快照
│       ├── eval/            # 评测结果
│       ├── analysis/        # 分析报告
│       ├── evolve/          # 本轮产生的变更
│       └── change_evaluation.json  # 预测 vs 实际
├── task_history.json        # 跨迭代任务追踪
├── iteration_scores.yaml    # 分数时序
└── best_ever.json           # 最佳版本指针
```

**实现**：
- `ExperimentManager` 类（TypeScript，~200 行）
- `init_experiment(config)`: 创建实验目录 + 快照当前 harness
- `record_iteration(n, results)`: 记录本轮结果
- `compute_iteration_diff(prev, cur)`: 9 状态变化矩阵
- `best_ever()`: 返回历史最佳版本

#### 任务 2：交叉迭代分析矩阵
直接移植官方的 9 状态分类：

```
flipped:           fail → pass     (改进成功 ✅)
regressed:         pass → fail     (退化 🚨 最高优先级)
stable_pass:       pass → pass     (稳定通过 ✅)
stable_fail:       fail → fail     (持续失败)
infra_recovered:   exception → pass
infra_lost:        pass → exception
exception_to_fail: exception → fail
fail_to_exception: fail → exception
exception_stable:  exception → exception
```

**实现**：`computeChangeMatrix(current, previous)` → 直接在 MemoryBus 里加

#### 任务 3：轻量轨迹分析器 `TraceAnalyzer`
官方 Agent Debugger 是部分闭源的，我们用自己的方式：

**输入**：OpenClaw session 的完整 trace（工具调用 + 输出 + 错误）
**输出**：结构化分析报告

不需要 ~10M token 的复杂分析——我们的场景是单一智能体，不是并发多任务。用 LLM 直接分析：

```
Trajectory → LLM (skill-crystallizer-prompt) → 
  {
    root_cause: "路径引用错误：使用了 C:\ 而非 D:\",
    affected_components: ["environment.md"],
    suggested_fix: "更新 environment.md 中的路径映射",
    confidence: 0.85,
    evidence: ["Step 3: 文件未找到异常", "Step 5: 路径解析失败"]
  }
```

**实现**：`TraceAnalyzer.analyze(sessionTrace)` → 调用 LLM 生成分析报告

### P1：强化独有护城河（Week 2-3）

#### 任务 4：污染防火墙 2.0
当前已有 4 维评分 + 3 级隔离，v3.0 增强：

1. **多模型交叉验证**（Grok R22 建议）
   - 对标记为 suspicious 的事件，用 2+ 模型重新验证
   - 验证分歧 > 阈值 → 升级到 isolated

2. **验证衰减可视化**
   - `suspicion_score` 随时间自然增长（τ=7天半衰期不变）
   - 在 SKILL.md 中标注"最后一次验证：X 天前"

3. **污染传播追踪**
   - 记录事件的依赖链
   - 如果上游事件被标记为 contaminated → 下游自动降权

#### 任务 5：技能结晶 2.0
当前已有 crystallize_skill，v3.0 增强：

1. **自动触发**（任务成功后自动结晶，不需要手动）
2. **技能对比去重**（结晶前检查是否已有类似技能，合并而非重复创建）
3. **技能效果追踪**（记录每次复用时的成功/失败）
4. **技能演化链**（一个技能的修改历史）

#### 任务 6：组件交互分析
论文发现组件间存在非加性交互（同时改 prompt 和 tool 效果不是两者之和）。

**实现**：
- 记录每次变更的组合（改了哪些组件）
- 对比"单独改组件 A" vs "同时改 A+B"的效果
- 发现协同/拮抗关系

### P2：首次 benchmark 验证（Week 3-4）

#### 任务 7：选 benchmark 跑首次循环
不选 Terminal-Bench 2（太重，需要 E2B），选适合 OpenClaw 的：

**候选**：
- **OpenClaw 内部评测**：用已有的 skill 评测体系
- **简单编程任务集**：5-10 个文件操作/搜索任务
- **脚本执行成功率**：自动化脚本的正确率

**目标**：3-5 轮迭代后 pass rate 有正向提升（哪怕是 5% → 15%）

#### 任务 8：分数追踪和自动回滚
- `iteration_scores.yaml` 持续追踪
- 如果本轮 pass rate 下降超过 10% → 自动回滚到上一版本
- 记录回滚原因（regression 的具体任务）

### P3：增强功能（Month 2+）

#### 任务 9：主动探索模式
不只是"失败后修复"，定期：
- 分析 patterns.md 中的高频失败模式
- 主动提出新组件或修改建议
- 实验沙盒（尝试性修改，跑一个子集验证）

#### 任务 10：一键运维
OpenClaw skill：`ahe status` / `ahe evolve` / `ahe rollback`
