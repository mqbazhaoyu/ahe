# 技能：Grok 架构协作

> **来源**：AHE 自进化过程，2026-05-17 与 Grok 25 轮对话经验结晶  
> **技能类型**：协作方法论  
> **适用场景**：需要设计复杂系统架构、技术选型、深度代码审查时

---

## 触发条件

- 任务涉及"设计架构"、"技术选型"、"系统融合"、"审查方案"
- 任务复杂度高（预计 5+ 步骤）
- 需要外部视角验证内部方案
- 用户说"问问 Grok" / "让 Grok 审查"

---

## 核心原则

### 1. 诚实批判第一（Round 1 经验）
- **第一轮必须要求 Grok 诚实批判**，不要糖衣
- 问法："仔细审查这个方案，列出所有可能失败的风险，不要委婉"
- 结果：Grok 在第一轮指出了 6 大架构风险，直接促成了从「融合 5 个桌面应用」→「提取算法为 OpenClaw 插件」的战略转向
- **这是 25 轮中最有价值的一轮**

### 2. 算法提取 > 应用胶合
- 不要让 Grok 帮你「胶合 5 个桌面应用」
- 正确方式：从现有项目（llm_wiki、OpenHuman、GenericAgent）中提取核心算法
- 提取结果：Louvain 社区发现、TokenJuice 压缩、4-signal KG 评分 → 全变成轻量 OpenClaw 插件
- Grok 确认："这个简化方向比原方案好得多"

### 3. 渐进式追问（不要一次问太多）
每轮只问 1-2 个深度问题，等 Grok 回答后再深入：
- R1: 批判 → R2: 提取算法 → R3: 周期设计 → R4: 公式化 → R5: 代码骨架
- 不要：一口气丢 10 个问题（会得到浅回答）
- 每次在上一轮基础上追问更深的实现细节

### 4. 要求具体输出（不要只说"怎么做"）
Grok 喜欢给抽象建议。强制他给具体产物：
- "给我一个 TypeScript 接口定义"（不是"用什么语言好"）
- "给我一个 LLM prompt"（不是"你应该写 prompt"）
- "给我具体的权重数值和公式"（不是"你需要一个公式"）

有效追问模式：
```
"说得好。现在给我具体的：
1. 代码骨架
2. 数据库 schema
3. LLM prompt"
```

### 5. 最终决策权在你自己
- Grok 给方向，你决定
- 例子：Grok 建议"先做 LanceDB + GenericAgent"，我们分析后决定"先做 Unified Memory Bus + Skill Crystallization"
- 告知 Grok 你的决策并要他基于此继续深入 → 他会在你的方向上深化

---

## 对话结构模板

```
第 1 轮：诚实批判（当前方案最大的 5 个风险是什么？）
第 2 轮：方案转向（如果改成 X 方向，可行吗？）
第 3 轮：具体化（给我 X 的具体设计）
第 4 轮：选优（A vs B vs C，哪个最好？为什么？）
第 5 轮：代码级（给我最小可工作的代码）
第 6 轮：排序（所有要做的事情，按优先级排）
第 7-10 轮：深化（每个优先级深入实现细节）
```

## 与特定模型协作的技巧

### Grok
- **强项**：架构批判、系统思维、诚实反馈、工程务实
- **弱项**：代码细节（给的代码经常有语法错误）、中文表达偶尔生硬
- **策略**：用 Grok 做架构设计和技术选型，不要用他做代码实现
- **关键指令**："不要委婉，直接说哪里会失败"

### ChatGPT
- **强项**：用户体验、产品思维、解释概念
- **弱项**：深度架构批判
- **策略**：用 ChatGPT 做 UX 设计、用户反馈模拟

### Claude
- **强项**：代码细节、TypeScript/React 实现、长文档处理
- **弱项**：有时过度谨慎
- **策略**：用 Claude 做代码审查和实现

---

## 踩过的坑

1. **❌ 让 Grok 生成完整可运行的代码** → 他给的代码需要大量修正（TypeScript 类型错误、LanceDB API 不对）
2. **✅ 让 Grok 生成设计规范和伪代码** → 这是他擅长的
3. **❌ 一次问太多问题（5+）** → 回答质量下降
4. **✅ 每轮 1-2 个深度问题** → 回答质量高
5. **❌ 跳过诚实批判阶段** → 容易陷入确认偏差
6. **✅ 第一轮强制批判** → 找到了最关键的架构问题

---

## 产出标准

一个成功的 Grok 协作应该产出：
- [ ] 1 份诚实批判报告（列出所有风险）
- [ ] 1 个简化后的架构方案
- [ ] 1 份具体的技术选型（A vs B vs C，有理由）
- [ ] 1 套可执行的优先级排序（TOP 3 MUST / TOP 3 DEFER）
- [ ] 1 份代码级规范（接口定义、schema、prompt）
- [ ] 1 份对话总结（保存到 manifest/ 目录）

---

## 进化指标

- **成功标志**：架构方案从「6 个风险」变成「0 个风险」→ Grok 最终给出 "excellent component synergy" 的评价
- **关键转折**：R2 的战略转向（从融合应用到提取算法）
- **复现性**：已验证（25 轮对话，从批判到代码实现，全过程可复现）
